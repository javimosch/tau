# Wire Emacs agent-shell to tau

[agent-shell](https://github.com/xenodium/agent-shell) (on MELPA, with its
dependency [acp.el](https://github.com/xenodium/acp.el)) is a native Emacs
client for ACP agents. Emacs config is elisp, not JSON — `tau setup`
can't splice your init file safely, so it always writes a paste-ready
snippet:

```
Emacs agent-shell ──ACP(stdio)──> tau acp serve
```

## Prerequisites

- Emacs 29.1+ with `agent-shell` and `acp` installed from MELPA.
- `tau` installed and configured — `tau doctor` reports an ok provider and
  API key (see [docs/configuration.md](../configuration.md)).

## One command

```bash
tau setup --client emacs --yes
```

Setup reports a `"manual"` outcome in its clients step — `"snippet_path"`
is the file to paste from and `"editor_detected"` tells you whether
`~/.emacs.d` exists:

```json
{"client":"emacs","editor_detected":true,"status":"manual","snippet_path":"/home/you/.config/tau/snippets/emacs.el","next":"paste the snippet into your init file, restart Emacs, run M-x agent-shell and pick tau"}
```

## What gets written

<!-- setup-verify: client-snippet -->
```elisp
;; tau ACP agent for agent-shell — generated by `tau setup --client emacs`.
;; Paste into your Emacs init file (~/.emacs.d/init.el or
;; ~/.config/emacs/init.el) and restart Emacs.
;; Requires agent-shell and acp.el from MELPA.
;; Full guide: https://github.com/javimosch/tau/blob/master/docs/clients/emacs.md

;; Register tau as a custom agent-shell agent.
(defun agent-shell-make-tau-config ()
  "Create a tau agent configuration for `agent-shell'."
  (agent-shell-make-agent-config
   :identifier 'tau
   :mode-line-name "tau"
   :buffer-name "tau"
   :shell-prompt "tau> "
   :shell-prompt-regexp "tau> "
   :needs-authentication nil
   :client-maker
   (lambda (_buffer)
     (acp-make-client
      :command "tau"
      :command-params '("acp" "serve")))))

(add-to-list 'agent-shell-agent-configs (agent-shell-make-tau-config))
;; Run M-x agent-shell and pick tau.
```

at `~/.config/tau/snippets/emacs.el`. The snippet's `:command` is the
absolute path of the tau binary setup ran from — Emacs's spawn
environment can't always resolve a bare `tau` from your interactive
shell's PATH.

> The fenced block above is verified — the `client-guides` smoke group
> ([scripts/check-client-guides.py](../../scripts/check-client-guides.py))
> diffs it byte-for-byte against real `tau setup --client` output in CI.

## Manual setup

Paste the verified block into your init file yourself:

- `~/.emacs.d/init.el`, or `~/.config/emacs/init.el` if you use the XDG
  layout.
- Replace `:command "tau"` with the absolute path to your tau binary
  (`command -v tau`) unless `tau` is on the PATH Emacs sees (check with
  `M-x getenv RET PATH RET`).
- If the spawned tau process needs credentials it can't get from
  `~/.config/tau/config.json`, pass them via
  `:environment-variables '("XIAOMI_API_KEY=…")` in the
  `acp-make-client` call.

The `:client-maker` lambda receives the shell buffer — the snippet names
it `_buffer` and ignores it. `agent-shell-make-agent-config` and
`acp-make-client` are both part of the installed agent-shell/acp.el
packages; no other dependency is needed.

## Finish in Emacs

1. Restart Emacs (or `eval-buffer` your init file).
2. Run `M-x agent-shell` and pick **tau** — agent-shell spawns
   `tau acp serve` over stdio and opens the agent's shell buffer.

`tau doctor` reports the wiring as the `client_emacs` check — always a
skip, since elisp config can't be verified automatically.
