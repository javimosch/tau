# Wire Neovim to tau

Neovim reaches ACP agents through Lua plugins —
[avante.nvim](https://github.com/yetone/avante.nvim) and
[CodeCompanion.nvim](https://github.com/olimorris/codecompanion.nvim) both
know the protocol. Plugin config is Lua, not JSON — `tau setup` can't
splice your `init.lua` safely, so it always writes a paste-ready snippet:

```
Neovim (avante.nvim / CodeCompanion.nvim) ──ACP(stdio)──> tau acp serve
```

## Prerequisites

- Neovim with [avante.nvim](https://github.com/yetone/avante.nvim) **or**
  [CodeCompanion.nvim](https://github.com/olimorris/codecompanion.nvim)
  installed.
- `tau` installed and configured — `tau doctor` reports an ok provider and
  API key (see [docs/configuration.md](../configuration.md)).

## One command

```bash
tau setup --client nvim --yes
```

Setup reports a `"manual"` outcome in its clients step — `"snippet_path"`
is the file to paste from and `"editor_detected"` tells you whether
`~/.config/nvim` exists:

```json
{"client":"nvim","editor_detected":true,"status":"manual","snippet_path":"/home/you/.config/tau/snippets/nvim.lua","next":"pick the tau provider/adapter in your plugin (e.g. :AvanteSwitchProvider)"}
```

## What gets written

<!-- setup-verify: client-snippet -->
```lua
-- tau ACP agent snippets for Neovim — generated by `tau setup --client nvim`.
-- Paste the block for your plugin into your Neovim config and restart.
-- Full guide: https://github.com/javimosch/tau/blob/master/docs/acp.md

-- avante.nvim ---------------------------------------------------------------
require("avante").setup({
  provider = "tau",
  acp_providers = {
    ["tau"] = {
      command = "tau",
      args = { "acp", "serve" },
      env = {},
    },
  },
})
-- If "tau" isn't the default provider, pick it with :AvanteSwitchProvider.

-- CodeCompanion.nvim --------------------------------------------------------
require("codecompanion").setup({
  adapters = {
    acp = {
      tau = function()
        local helpers = require("codecompanion.adapters.acp.helpers")
        return {
          name = "tau",
          formatted_name = "tau",
          type = "acp",
          roles = { llm = "assistant", user = "user" },
          commands = {
            default = { "tau", "acp", "serve" },
          },
          defaults = { timeout = 20000 },
          parameters = {
            protocolVersion = 1,
            clientCapabilities = {
              fs = { readTextFile = true, writeTextFile = true },
            },
            clientInfo = { name = "CodeCompanion.nvim", version = "1.0.0" },
          },
          handlers = {
            setup = function(self) return true end,
            auth = function(self) return true end,
            form_messages = function(self, messages, capabilities)
              return helpers.form_messages(self, messages, capabilities)
            end,
            on_exit = function(self, code) end,
          },
        }
      end,
    },
  },
})
-- Then pick the "tau" adapter in a chat buffer.
```

at `~/.config/tau/snippets/nvim.lua`. The snippet's `command` is the
absolute path of the tau binary setup ran from — a GUI-launched Neovim
can't always resolve a bare `tau` from your interactive shell's PATH.

> The fenced block above is verified — the `client-guides` smoke group
> ([scripts/check-client-guides.py](../../scripts/check-client-guides.py))
> diffs it byte-for-byte against real `tau setup --client` output in CI.

## Manual setup

Paste the block for *your* plugin into `init.lua` (or a file it sources)
yourself — you only need one of the two adapters:

- **avante.nvim**: merge the `acp_providers.tau` entry into your existing
  `require("avante").setup({...})` call and set `provider = "tau"` (or
  switch at runtime with `:AvanteSwitchProvider`).
- **CodeCompanion.nvim**: merge the `adapters.acp.tau` factory into your
  existing `require("codecompanion").setup({...})` call, then pick the
  `tau` adapter in a chat buffer.
- Replace `command = "tau"` (avante) or the `default` table's first entry
  (CodeCompanion) with the absolute path to your tau binary
  (`command -v tau`) unless `tau` is on the PATH Neovim sees.
- If the spawned tau process needs credentials it can't get from
  `~/.config/tau/config.json`, put them in the `env` table (avante) — e.g.
  `env = { XIAOMI_API_KEY = os.getenv("XIAOMI_API_KEY") }`.

## Finish in Neovim

- **avante.nvim**: restart Neovim, run `:AvanteSwitchProvider` if tau
  isn't the default, and pick **tau**.
- **CodeCompanion.nvim**: restart Neovim, open a chat buffer
  (`:CodeCompanionChat`), and select the **tau** adapter.

`tau doctor` reports the wiring as the `client_nvim` check — always a
skip, since Lua config can't be verified automatically.
